Módulo 07 · Módulo Final

Avaliação (Eval) — Como Medir se a IA Está Funcionando

Você mudou um prompt — melhorou ou piorou? Sem eval, você está chutando.

Seção 1

Por que Avaliar?

"Funciona" não é uma métrica. Toda vez que você muda um prompt, adiciona um novo tool, ou troca de modelo, você precisa saber: ficou melhor ou pior?

Eval para IA é igual a testes automatizados para código.
Você não faria deploy de código sem rodar os testes. Não faça deploy de um agente de IA sem rodar os evals. A diferença é que testes verificam comportamento determinístico — evals verificam qualidade, que é probabilística e subjetiva.

Sem evals você cai nessa armadilha comum: ajusta o prompt para um caso, testa manualmente três exemplos, acha que ficou melhor — mas na prática quebrou 40 outros casos que você não testou. Isso é regressão silenciosa.

Exercício Rápido — Qual resposta é melhor?
Pergunta do cliente: "Quando meu pedido #4521 vai chegar?"
Resposta A
"Olá! Verifiquei seu pedido #4521. Ele saiu do nosso centro de distribuição em São Paulo ontem às 14h e está previsto para chegar até amanhã às 18h. Você receberá um SMS de confirmação quando sair para entrega. Posso ajudar com mais alguma coisa?"
Resposta B
"Pedidos costumam levar de 3 a 7 dias úteis dependendo da sua região. Para verificar o status específico do seu pedido, acesse o site e use o número de rastreamento que enviamos por email no momento da compra. Espero que isso ajude!"
Correto! Resposta A é melhor. Ela é específica, usa o número do pedido, dá uma data concreta e oferece próximos passos claros. A Resposta B é genérica e joga o trabalho de volta para o cliente.

Agora imagine fazer essa avaliação 1.000 vezes por dia manualmente. É insustentável. É por isso que precisamos de eval automatizado.

Seção 2

Tipos de Avaliação

Existem três abordagens principais — e times maduros usam as três em combinação.

👥
Avaliação Humana
Pessoas avaliam as saídas da IA com critérios definidos (escala 1–5, preferência entre duas opções, aprovação/rejeição).
Captura nuances que código não percebe
Identifica comportamentos inesperados
Lento e caro para escalar
Avaliadores distintos = inconsistência
Quando usar: início do desenvolvimento e edge cases
⚙️
Avaliação Automática (Heurística)
Código verifica propriedades da saída: formato JSON válido? Contém campos obrigatórios? Comprimento dentro do limite? Referencia o número do pedido?
Rápido, consistente, escalável
Zero custo marginal por execução
Não avalia qualidade ou nuance
Pode gerar falsos positivos
Quando usar: validação de formato e checks básicos
🤖
LLM-as-a-Judge
Um modelo mais forte (ex: GPT-4o) avalia as respostas de um modelo mais barato (ex: GPT-4o-mini). Você escala qualidade com IA avaliando IA.
Escalável — roda 24/7 sem intervenção
Entende nuance como humano
Pode ter vieses (prefere suas próprias respostas)
Tem custo financeiro por chamada
Quando usar: avaliação de qualidade em escala
Na prática: use heurísticas para validação de formato (free), LLM-as-Judge para avaliação de qualidade em CI/CD, e avaliação humana para novos comportamentos e calibração periódica.
Seção 3

Métricas Comuns

Cada métrica mede uma dimensão diferente da qualidade. Um sistema de prod geralmente monitora várias em paralelo.

Dica prática: não tente medir tudo ao mesmo tempo. Comece com as 2–3 métricas mais críticas para o seu caso de uso. Para um chatbot de suporte: relevância + completude + tom. Para um gerador de código: acurácia + execução sem erros.

Seção 5

O Ciclo Eval → Melhoria

Eval não é um evento único — é um ciclo contínuo idêntico ao TDD (Test-Driven Development).

Criar prompts
/ agentes
→
Testar com
eval dataset
→
Medir
métricas
→
✓ Bom o suficiente?
Deploy + monitorar
✗ Não? Ajustar
→ reiniciar ciclo
TDD vs. Eval — são a mesma ideia
TDD (código)
1. Escreve o teste
2. Escreve o código
3. Roda os testes
4. Corrige falhas
5. Repete
Eval (IA)
1. Escreve os casos de eval
2. Escreve o prompt
3. Roda os evals
4. Corrige regressões
5. Repete

A grande diferença: em TDD o teste passa ou falha (binário). Em eval, o resultado é uma pontuação ou distribuição — e você define o limiar aceitável para o seu contexto.

Seção 6

Ferramentas de Eval

Você não precisa construir tudo do zero. Escolha a ferramenta certa para o seu estágio.

Promptfoo
Open Source
Focado em devs. CLI-based, fácil de integrar ao CI/CD. Ideal para testar prompts contra datasets locais com múltiplos modelos.
Braintrust
Cloud
Plataforma completa: logging, experimentação, comparação de versões de prompt. Boa para times que precisam de visibilidade compartilhada.
LangSmith
Cloud
Do ecossistema LangChain. Excelente para tracing de agentes complexos — você vê cada passo, tool call e decisão do agente.
Scripts customizados
Custom
Às vezes um script Python com assertions e um CSV de casos de teste é tudo que você precisa. Não superengenheire antes de ter a necessidade.
Regra prática: comece com scripts simples. Quando você tiver mais de 50 casos de teste e múltiplos membros do time avaliando, considere uma plataforma dedicada.
