Seção 1 / 6

De Prompt Engineering para Context Engineering

Prompt engineering ficou famoso como a arte de escrever perguntas melhores para uma IA. "Seja conciso", "pense passo a passo", "aja como um especialista" — você provavelmente já viu esses conselhos.

Mas isso é só uma fatia do problema. O modelo não recebe apenas a sua mensagem. Ele recebe tudo que está na janela de contexto — e você controla muito mais do que imagina.

Analogia
"Prompt é uma pergunta. Contexto é toda a reunião — quem está na sala, quais documentos estão na mesa, qual o histórico da conversa, quais ferramentas estão disponíveis."

Context engineering é a disciplina de projetar intencionalmente tudo que entra no contexto do modelo: instruções do sistema, histórico de conversa, documentos recuperados, ferramentas disponíveis — e também o que deliberadamente não entra.

Seção 2 / 6

A Janela de Contexto

O modelo não tem memória infinita. Ele só consegue "ver" o que está dentro da sua janela de contexto — uma quantidade limitada de texto, medida em tokens (aproximadamente ¾ de uma palavra em inglês, ou uma sílaba em português).

Metáfora
"É como uma mesa de trabalho. Uma mesa maior permite ter mais documentos abertos ao mesmo tempo. Mas mesmo a maior das mesas tem um limite — e você precisa decidir o que merece estar nela."

Mesmo com janelas cada vez maiores, o problema de o que priorizar não desaparece. Pesquisas mostram que modelos perdem atenção para informações no meio de contextos muito longos — fenômeno chamado "lost in the middle". Qualidade importa mais que quantidade.

Seção 3 / 6

Os 5 Componentes do Contexto

Cada elemento que você coloca no contexto tem um papel específico. Entender o papel de cada um é o primeiro passo para projetar contextos eficientes.

System Prompt — A Constituição

O system prompt é o conjunto de regras que sempre se aplica, independente do que o usuário diga. É a "constituição" do seu assistente — define persona, restrições, formato de resposta e contexto de negócio.

# Exemplo simplificado de system prompt Você é um assistente de suporte técnico da TechStore. REGRAS: - Sempre responda em português - Não compartilhe informações de outros clientes - Se não souber, diga "Vou verificar com o time" - Tom: profissional mas amigável CONTEXTO: - Produto: loja online de eletrônicos - Usuários: clientes com dúvidas sobre produtos e pedidos
Dica
Um bom system prompt é específico o suficiente para guiar o comportamento, mas flexível o suficiente para o modelo exercer julgamento. Regras demais criam rigidez. Regras de menos criam imprevisibilidade.
Memória — Curto vs. Longo Prazo

Modelos de linguagem não têm memória nativa entre sessões. Cada conversa começa do zero. Para simular memória, precisamos injetá-la deliberadamente no contexto.

⚡ Curto prazo — histórico da conversa atual
💾 Longo prazo — arquivos, banco de dados, vetores

Veja a diferença entre um assistente SEM e COM memória:

Sem memória
Pode me chamar de Ana.
Claro! Como posso ajudar?
Qual é o meu plano atual?
Poderia me informar seu nome para verificar?
Com memória
Pode me chamar de Ana.
Claro, Ana! Como posso te ajudar?
Qual é o meu plano atual?
Ana, seu plano atual é o Pro — conforme o histórico de sessões anteriores.
Ferramentas — O Modelo Que Age

Ferramentas transformam o modelo de um gerador de texto em um agente que age. Em vez de descrever o que faria, ele pode realmente fazer.

💬 Simulação — "Qual é a previsão do tempo em São Paulo?"
USUÁRIO
Qual é a previsão do tempo em São Paulo hoje?
ASSISTENTE (sem ferramentas)
Não tenho acesso a informações em tempo real, então não consigo fornecer a previsão exata de hoje. Recomendo verificar um app de meteorologia como Weather.com ou INMET.

Com ferramentas, o modelo pode: buscar na web, consultar bancos de dados, executar código, chamar APIs, ler e escrever arquivos — e combinar múltiplas ferramentas para resolver tarefas complexas.

RAG — Recuperar em vez de Memorizar

RAG (Retrieval-Augmented Generation) resolve o problema de janela de contexto limitada. Em vez de colocar tudo no contexto, você recupera apenas o que é relevante para a pergunta atual.

Sem RAG
Você tem 500 páginas de documentação. Coloca tudo no contexto. O modelo fica lento, caro e confuso com informação irrelevante.
Com RAG
O usuário faz uma pergunta. O sistema busca as 3 páginas mais relevantes. Só essas 3 entram no contexto. Modelo rápido, barato e focado.
Preview
RAG será explorado em profundidade no Módulo 5. Por ora, lembre-se: o objetivo é recuperar o contexto certo, não recuperar o máximo de contexto.
Histórico de Conversa — O Que Guardar?

Manter todo o histórico de uma conversa longa consome tokens valiosos. Estratégias inteligentes comprimem sem perder o essencial:

📝
Manter completo
Conversas curtas onde cada mensagem anterior é relevante.
🗜️
Sumarizar
Comprime mensagens antigas em um resumo. O próprio modelo pode fazer isso.
🎯
Janela deslizante
Mantém apenas as últimas N mensagens. Simples e efetivo para chats lineares.
🔍
Recuperação seletiva
Busca mensagens antigas relevantes para a pergunta atual. Como RAG para o histórico.

Context Engineering na Prática

Os conceitos desta aula não são teóricos — você já os usa, talvez sem saber o nome certo. Ferramentas modernas de desenvolvimento com IA são, no fundo, sistemas de context engineering.

📋
System Prompt
O arquivo de instruções que você cria para a IA entender seu projeto. Define regras, convenções, arquitetura e anti-padrões.
System Prompt
🗂️
Memória do Projeto
Arquivos que guardam decisões, lições e estado do projeto. São memória de longo prazo injetada no contexto a cada nova sessão.
Memória persistente
🔌
MCP Servers
Model Context Protocol — servidores que expõem ferramentas para o modelo: banco de dados, filesystems, APIs externas, browsers.
Ferramentas
🤖
Subagentes
Quando um agente chama outro, cada um tem seu próprio contexto isolado. Evita poluição entre tarefas e otimiza o uso de tokens.
Isolamento de contexto
Princípio fundamental
"Coloque no contexto apenas o que é relevante para a tarefa atual. Contexto irrelevante é ruído — e ruído degrada qualidade, aumenta custo e confunde o modelo."
